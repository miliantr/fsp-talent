# FSP Talent — подбор ИТ-специалистов с верифицированным профилем ФСП

Цифровая платформа с **обратной механикой подбора**: кандидат проходит тест на заявленный грейд и
получает объективную категорию («Backend · Middle»), профиль автоматически обогащается достижениями
Федерации спортивного программирования, а **работодатель сам** описывает потребность, получает
ранжированную и объяснимую подборку и направляет конкретному человеку приглашение с зарплатной вилкой.

> MVP для спецтрека ФСП «Цифровая платформа-агрегатор ИТ-вакансий с верифицированным профилем
> достижений участника». Всё ниже работает «из коробки» на демо-данных.
>
> **Уточнения заказчика** (ответы на вопросы команд) и что по каждому сделано — в
> [docs/clarifications.md](docs/clarifications.md): адресные регулярные задания с автопроверкой и
> рубрикой, несколько категорий, статус «грейд не подтверждён», проверка честности теста по поведению,
> тест–ретест всей процедуры и анализ разделяющей силы каждого задания, профильность дисциплин ФСП.

**Русский и английский.** Интерфейс, ответы сервера (ошибки, объяснения подбора, рекомендации по
тесту, справочники, письма) и весь банк заданий доступны на двух языках. Язык определяется по
браузеру, переключается RU / EN на любом экране и сохраняется в учётной записи. Тест можно проходить
на любом языке и переключать по ходу — варианты ответов и калибровка общие
([docs/architecture.md](docs/architecture.md#7-локализация-ru--en)).

## Сквозной сценарий демонстрации

1. **Кандидат**: «Регистрация» → код подтверждения (в демо виден на экране и в Mailpit) → профиль
   (можно загрузить PDF-резюме) → «Тестирование»: опрос — Backend, Middle → «Начать тест» → 20 вопросов
   → результат: грейд, категория, шкальный балл, компетенции, уверенность → «Достижения ФСП» →
   «Настройки»: включить публикацию профиля.
2. **Работодатель** `hr@demo.ru`: «Новая потребность» → описать текстом («Middle Python, FastAPI,
   PostgreSQL, Docker, 180–250 тыс., удалёнка») → «Разобрать описание» → «Получить подборку» →
   рекомендованные категории и рейтинг с объяснением → «Профиль и объяснение» (вклад факторов, контакты
   скрыты) → «Пригласить» (вилка обязательна).
3. **Кандидат**: «Приглашения» → компания, предложение, **зарплата до ответа**, «почему выбрали вас» →
   «Принять» → у работодателя открываются e-mail, телефон, Telegram.
4. **Регулярные задания**: кандидат в «Коротких заданиях» видит задачу, которую система предложила
   именно ему («работодатель рассматривает вас для „Python Backend Developer“»), отвечает; работодатель
   в «Коротких заданиях» видит предварительную оценку по ключевым идеям и ставит оценку по рубрике —
   в подборке появляется «свежий сигнал».

Дополнительно: сравнение кандидатов «почему A выше B», банк кандидатов с фильтрами, публичные
вакансии и отклики, несколько категорий у кандидата, жалоба на приглашение, PDF-профиль.

**Видео сценария** (≈6 мин, 6 глав: кандидат, работодатель, ответ кандидата, регулярные задания, отклик,
два языка; субтитры объясняют механики тестирования и подбора) записывается на
запущенном стенде: `pip install playwright imageio-ffmpeg && python -m playwright install ffmpeg`,
затем `python scripts/record_demo.py` → `presentation/FSP_Talent_demo.mp4` (демо-данные сбрасываются
до и после записи).

## Ключевые механики

**Подбор** ([docs/matching.md](docs/matching.md)). Объяснимая формула из 9 компонентов: стек через
граф навыков с учётом *доказательности* (подтверждён ли навык тестом), подтверждённый грейд, результат
теста относительно требуемого уровня, специализация, ФСП (нет истории = нейтральная база, без штрафа;
вес достижения зависит от профильности дисциплины), актуальность и «свежий сигнал» регулярных заданий,
зарплата, опыт, формат + мягкое «И» для обязательных навыков. Каждый процент разложен на вклады
факторов; есть сравнение A vs B; подборка сохраняется и уточняется фильтрами. У кандидата может быть
до трёх категорий — в подборке его представляет категория специализации потребности.

**Тестирование** ([docs/testing.md](docs/testing.md)). Банк из 252 калиброванных заданий и
25 параметрических семейств (новые числа для каждого кандидата) по 4 специализациям и 21 компетенции.
Индивидуальный вариант собирается по единому плану (blueprint) — одинаковые квоты компетенций и
профиль сложности; оценка по IRT (3PL, EAP) делает результаты разных вариантов сопоставимыми.
Детектор утечки (person-fit + разрыв «статические vs параметрические задания») и проверка поведения
(уходы со вкладки, вставка, быстрые верные ответы на трудные для кандидата вопросы) требуют
подтверждающей формы. Заявленный грейд без теста помечается «не подтверждён». Кулдауны: повтор через
30 дней, смена грейда — раз в 90 дней (у каждой категории свой срок), тест ниже — сразу после провала,
тест выше — сразу после уверенного результата.

**Регулярные задания** ([docs/testing.md §8](docs/testing.md#8-регулярные-задания-servicestasks_servicepy)).
Система раз в неделю предлагает кандидату задачу от работодателя — по грейду, по потребности, где его
уже рассматривают, по слабо подтверждённой компетенции. Автопроверка (число / текст) или подход с
рубрикой работодателя (корректность, полнота, обоснование); предварительная оценка по ключевым идеям
помогает разбирать ответы. Результат — свежий сигнал в подборке; грейд меняет только тест.

**ФСП** ([docs/fsp-integration.md](docs/fsp-integration.md)). Порт `FSPRegistry` с мок-адаптером и
HTTP-адаптером, мок-API реестра, автопривязка по подтверждённому e-mail, ручная привязка ФСП ID с
подтверждением владения, совместимость с Keycloak (OIDC-claims в JWT).

## Архитектура

```
frontend/   React 19 + TypeScript + Vite; типы API генерируются из OpenAPI
  src/i18n/           словари RU / EN, плюрализация, форматирование, переключатель языка
  src/**/*.test.ts*   124 теста (Vitest + Testing Library)
backend/    FastAPI · SQLAlchemy 2 · Alembic · PostgreSQL (SQLite локально)
  app/api/            REST-роутеры (без бизнес-логики)
  app/services/       сценарии: auth, кандидат, категории, работодатель, приглашения, приватность, задания
    testing/          Testing Engine: банк → blueprint → генерация → IRT → правила грейдов → честность
    matching/         Matching Engine: признаки → скоринг → объяснение → снимок подборки
    fsp/              порт реестра ФСП, адаптеры, сила сигнала
    nlp/              разбор PDF-резюме и текстового описания потребности (RU / EN)
  app/i18n/           язык запроса (Accept-Language), каталоги сообщений RU / EN
  app/repositories/   доступ к данным
  app/models/         26 таблиц, миграции в alembic/
  app/domain/         справочники и банк заданий
  app/seed/           демо-данные (кандидаты проходят настоящий движок тестирования)
  tests/              446 тестов (pytest): движки, категории, задания, честность, приватность, локализация
  scripts/            экспорт OpenAPI, анализ заданий по реальным попыткам (item_analysis.py)
evaluation/  офлайн-валидация тестирования и подбора
docs/        архитектура, механики, интеграция ФСП, API, развёртывание
```

## Ограничения MVP

* Реестр ФСП — синтетический мок (реальный API не предоставлен); интеграция заменяется адаптером.
* Пороги проверки поведения подобраны на модели времени ответа; на пилоте их стоит уточнить по
  реальным попыткам (скрипт анализа заданий и журнал проверок готовы).
* Параметры заданий — экспертная калибровка; процедура перекалибровки по ответам реализована и
  проверена на симуляции, но требует пилота на реальных кандидатах.
* Веса матчинга подобраны на синтетическом бенчмарке; после запуска — дообучение на исходах приглашений.
* Демо-режим показывает код подтверждения в интерфейсе (`EMAIL_DEV_EXPOSE_CODE=false` отключает).
* Пользовательские тексты (резюме, описания вакансий, названия соревнований ФСП) не переводятся.
  Английская версия заданий использует ту же калибровку — на пилоте стоит проверить эквивалентность
  заданий между языками (DIF-анализ).
* Защита от недобросовестных работодателей и интеграция с ATS — концепция + базовые меры (лимиты,
  валидация вилок, жалобы), см. [docs/architecture.md](docs/architecture.md).
