# Интеграция с реестром ФСП

API реестра ФСП на хакатоне не предоставляется, поэтому реализованы **порт** и два **адаптера**:
платформа зависит только от интерфейса, замена мока на реальную интеграцию не затрагивает
бизнес-логику.

```python
class FSPRegistry(Protocol):              # backend/app/services/fsp/registry.py
    source: str
    def get_participant(self, fsp_id: str) -> RegistryParticipant | None: ...
    def find_by_email(self, email: str) -> RegistryParticipant | None: ...
```

| Адаптер | Режим (`FSP_REGISTRY_MODE`) | Описание |
|---|---|---|
| `MockFSPRegistry` | `mock` (по умолчанию) | Синтетический снимок реестра `mock_data/fsp_registry.json` |
| `HttpFSPRegistry` | `http` | REST-клиент; контракт ниже. Мок-API поднят самим backend: `/api/mock-fsp/v1` |

## Контракт REST API реестра

GET /participants?email=<e-mail>     → 200 Participant | 404

Набор полей выбран так, чтобы работодатель понимал **уровень** (тип соревнования, место среди скольких
участников), **релевантность** (дисциплина, роль в команде) и **проверяемость** (ссылка на сертификат).
Дисциплины соответствуют направлениям ФСП: продуктовое, алгоритмическое программирование,
информационная безопасность, программирование БАС и робототехники.

## Связь профиля с ФСП ID

1. **Автоматически**: после подтверждения e-mail кандидата выполняется поиск в реестре по e-mail
   (`fsp_service.try_auto_link`). Найден — профиль обогащается без действий пользователя.
2. **Вручную**: кандидат вводит ФСП ID. Если e-mail в реестре совпадает — привязка мгновенная; иначе
   код подтверждения отправляется на e-mail из реестра (владение подтверждается, чужие достижения
   присвоить нельзя). Один ФСП ID — один профиль (UNIQUE + проверка, 409).
3. **Целевое состояние**: вход «через ФСП ID» на Keycloak. Токен Keycloak содержит `sub` участника —
   он сохраняется в `users.external_subject`, шаг с кодом заменяется OIDC-авторизацией.

Данные кешируются локально (`fsp_profiles`, `fsp_achievements`) с отметкой `synced_at` и источником;
кнопка «Синхронизировать» перечитывает реестр. Отвязка удаляет локальный снимок.

## Как ФСП влияет на ранжирование

Сила сигнала для специализации `s` (`services/fsp/scoring.py`):

```
points(a) = level_weight(a.level) × place_factor(a.place, a.participants_total)
            × recency(0.5 ^ (years / 2.5)) × relevance(a.discipline, a.role, s)
strength  = 1 − exp(−(Σ points + rank_bonus) / 1.2)          ∈ [0, 1)
```

* `level_weight`: международные 1.0, всероссийские 0.85, межрегиональные 0.6, региональные 0.45;
* `place_factor`: 1 место 1.0, 2 — 0.85, 3 — 0.75, топ-10% — 0.55, топ-30% — 0.4, участие — 0.25;
* `relevance`: роль в команде совпадает со специализацией — 1.0, иначе матрица «дисциплина ×
  специализация» (например, ИБ → DevOps 0.9, алгоритмическое → Backend 0.8). Заказчик уточнил: все
  дисциплины ФСП одинаково приоритетны, но учитывать актуальность направления разумно — специалист по
  ИБ с соревнованиями по ИБ релевантнее, чем с робототехникой. Поэтому базовые веса от дисциплины не
  зависят, а близость дисциплины к специализации потребности умножает вклад достижения и показывается
  работодателю: «профильная дисциплина» (≥ 0,75), «смежная» (≥ 0,45), «другое направление»;
* `rank_bonus`: КМС/МС/разряды.

В Matching Engine компонент ФСП = `0.3 + 0.7 × strength`. **Отсутствие истории ФСП ≠ 0**: используется
нейтральная база 0.3, сигнал считается «недоступным», и кандидат не штрафуется; любое участие может
только поднять профиль. Валидация: идеальные кандидаты без ФСП в среднем находятся на 4,5-м перцентиле
выдачи против 3,6-го у кандидатов с ФСП (см. [matching.md](matching.md)). Кандидат может скрыть ФСП в
настройках — тогда сигнал не используется и в ранжировании.

## UI

* Кандидат: страница «Достижения ФСП» — список с медалями, уровнем, местом, командой, ролью; сила
  сигнала; привязка/синхронизация/отвязка; явное сообщение «История ФСП не найдена — это нормально».
* Работодатель: бейдж «N достижений ФСП» в карточке, лучшая позиция в объяснении («2 место — … ·
  профильная дисциплина»), полный список в профиле с отметкой профильности каждого достижения для
  специализации потребности; фильтр «есть / нет достижений ФСП» в подборке и банке кандидатов.
